# AI活用によるデータ入力・採算管理システムとセキュリティに関する会議

- **コンテキスト**: 社労士の加藤氏が、顧客（自動車部品工場）向けのデータ入力・採算管理システムをAIで構築する方法と、その際の法人利用におけるセキュリティ懸念について、「アシュラ」運営側に相談する目的で開催された会議。

### 📋 会議要約
本会議は、社労士の加藤氏が顧客の採算管理業務をAIで効率化するシステムの構築方法について相談したものです。主な論点は、法人データを扱う上でのセキュリティリスクとその対策でした。

対策として、機密データを直接AIに送信するのではなく、**AIに「データをローカルで処理するプログラム」を生成させるアプローチ**が提案されました。これにより、情報漏洩リスクを低減できることが示されました。話者Bは、Code Interpreter（コーデックス）を用いて、簡単な指示でスプレッドシートにダミーデータを生成するデモを実演しました。

また、加藤氏が週末の交流会で「アシュラ」を紹介するにあたり、LP（ランディングページ）やスライドを自動生成する**「奥義」機能**、特に「LPメーカー」のデモが効果的であるとのアドバイスがありました。

最終的に、加藤氏は顧客のデモデータでシステム構築を試みつつ、「奥義」機能を活用して自身の情報発信を強化していく方針を確認しました。

### 📌 決定事項
- **セキュリティ対策**: 機密データを扱う際は、AIに直接データを入力するのではなく、AIに「データをローカル環境で処理するプログラム」を生成させるアプローチを取ることで合意。
- **交流会での発表方針**: 今週末の交流会では、「アシュラ」の「奥義」機能、特に「LPメーカー」を使い、専門知識がなくても高品質なコンテンツが自動生成できる点をデモンストレーションする。
- **情報共有の場**: 今後の「アシュラ」に関する質疑応答や進捗報告は、主に「アシュラ」のFacebookコミュニティを活用して行うことを確認。

### 💡 補足・注意点
- **PCスペックの重要性**: Code Interpreter（コーデックス）や画面共有を同時に行うと、PCに高い負荷がかかる可能性がある。加藤氏のPCでも動作が重くなる場面が見られたため、安定した利用にはある程度のPCスペックが求められる。
- **実践の必要性**: デモを見て理解したつもりでも、実際に自分で手を動かしてみないと習熟は難しい。会議中に話者Bから、その場で実践してみることの重要性が繰り返し強調された。
- **「奥義」機能の前提条件**: 「アシュラ」の「奥義」は、画像生成などの高度な機能を実現するためにCode Interpreterをベースに構築されている。そのため、利用にはCode Interpreterが使える環境が必須となる。
- **AIツールの進化**: 「どのAIを使うか」という議論は終わり、「いかにAIに触れ、エージェントとして動かすか」が重要になっている、という業界の潮流が共有された。
